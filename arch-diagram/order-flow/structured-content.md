# Architecture: 电商订单流程 (E-commerce Order Flow)

## Layout

- 类型:swimlane(横向泳道)
- 风格:minimal-mono(黑白论文)
- 用途:技术评审 / 论文 / 专利附图

## Lanes (4 条泳道,从上到下)

1. **用户 (Customer)** — 发起方
2. **订单中心 (Order Center)** — 编排中枢
3. **支付服务 (Payment)** — 资金处理
4. **仓储 (Warehouse)** — 履约发货

## Steps (8 步,从左到右)

| # | 步骤 | 泳道 | 说明 |
|---|------|------|------|
| 1 | 提交订单 | 用户 | 填写收货地址、确认商品 |
| 2 | 创建订单 | 订单中心 | 生成订单号、锁库存 |
| 3 | 发起支付 | 订单中心 | 调用支付网关 |
| 4 | 扣款处理 | 支付服务 | 风控校验、扣账 |
| 5 | 支付成功 | 订单中心 | 更新订单状态、通知仓储 |
| 6 | 拣货打包 | 仓储 | 出库准备 |
| 7 | 发货配送 | 仓储 | 物流出库 |
| 8 | 确认收货 | 用户 | 完成订单 |

## Critical Paths (回退分支)

- 步骤 4(扣款)失败 → 回退到步骤 2(创建订单),用户重试或改支付方式
- 用虚线 + 反向箭头表示回退

## Relationships

- 1→2:用户提交,跨道下行
- 2→3:订单中心内部流转(同道水平)
- 3→4:调起支付,跨道下行
- 4→5:支付回调,跨道上行
- 5→6:通知仓储,跨道下行
- 6→7:仓储内部流转(同道水平)
- 7→8:送达用户,跨道上行
- 4→2(失败):回退,虚线反向
