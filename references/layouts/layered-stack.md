# layered-stack

分层堆栈布局，适用于云架构、技术栈、平台层级展示。

## 结构

从上到下分层，每层可包含多个并列模块，层间用箭头表示依赖或数据流。

```
┌─────────────────────────────────────────────────────────────┐
│                      Layer 1: 应用层                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐    │
│  │ Module A │  │ Module B │  │ Module C │  │ Module D │    │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      Layer 2: 平台层                         │
│  ┌──────────────────────────────────────────────────────┐  │
│  │                    Platform X                         │  │
│  └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                      Layer 3: 基础设施层                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                  │
│  │ Infra A  │  │ Infra B  │  │ Infra C  │                  │
│  └──────────┘  └──────────┘  └──────────┘                  │
└─────────────────────────────────────────────────────────────┘
```

## 典型层级（云架构）

| 层级 | 英文 | 典型内容 |
|------|------|----------|
| 应用层 | Application Layer | SaaS 应用、用户界面、API 网关 |
| 服务层 | Service Layer | BaaS 服务、微服务、业务逻辑 |
| 平台层 | Platform Layer | PaaS 平台、开发工具、CI/CD |
| 基础设施层 | Infrastructure Layer | IaaS、容器、计算资源 |
| 云原生能力 | Cloud Native | 存储、网络、安全、监控 |

## 层级数量

- **最少**：2 层（简化架构）
- **典型**：3-5 层（标准架构）
- **最多**：7 层（复杂架构）

## 间距规则

| 元素 | 间距 | 说明 |
|------|------|------|
| 层间距 | 80-120px | 层与层之间的垂直距离 |
| 模块间距 | 40-60px | 同层模块之间的水平距离 |
| 边界 padding | 30px | 层边界内的留白 |
| 箭头间距 | 20px | 箭头与模块的间距 |

## 模块排列

### 同层多模块

```
┌─────────────────────────────────────────────┐
│  ┌────┐    ┌────┐    ┌────┐    ┌────┐      │
│  │ M1 │    │ M2 │    │ M3 │    │ M4 │      │
│  └────┘    └────┘    └────┘    └────┘      │
└─────────────────────────────────────────────┘
```

- 水平等距排列
- 模块大小可一致，也可根据内容调整
- 保持视觉平衡

### 单模块跨层

```
┌─────────────────────────────────────────────┐
│  ┌──────────────────────────────────────┐   │
│  │           Wide Module                │   │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

- 适用于平台、网关等横跨型组件
- 宽度可占满整层

## 箭头类型（PPT 安全写法，禁用 `<marker>`）

> **强制规则**：本 skill 全部箭头都用 `<line>` + `<polygon>` 显式画。
> 线段画到终点前 9px，三角顶点对齐终点。这样在 PowerPoint 转形状后才不会丢箭头。

### 向下箭头 `(cx, y1)→(cx, y2)`

```svg
<line x1="200" y1="180" x2="200" y2="271" stroke="#64748B" stroke-width="2"/>
<polygon points="194,269 200,280 206,269" fill="#64748B"/>
```

公式：线段 `y2 = 终点-9`，三角 `points="cx-6,终点-11 cx,终点 cx+6,终点-11"`。

### 向右箭头 `(x1, cy)→(x2, cy)`

```svg
<line x1="160" y1="120" x2="231" y2="120" stroke="#64748B" stroke-width="1.5"/>
<polygon points="229,114 240,120 229,126" fill="#64748B"/>
```

公式：线段 `x2 = 终点-9`，三角 `points="终点-11,cy-6 终点,cy 终点-11,cy+6"`。

### 双向箭头 `(x1, cy)↔(x2, cy)`

两端各一个三角，中间是线段：

```svg
<line x1="171" y1="120" x2="229" y2="120" stroke="#64748B" stroke-width="1.5"/>
<polygon points="171,120 160,114 160,126" fill="#64748B"/>
<polygon points="229,120 240,114 240,126" fill="#64748B"/>
```

**双向箭头层间距建议 ≥ 40px**：两个三角各占 11px，线段中间至少要 18px 才能视觉上分清两端方向。间距 < 30px 时两个三角会挤在一起，看起来像单向箭头。

### 带标签的箭头

标签盒放在线段中点，**写在箭头之后**（保证不被三角遮挡）：

```svg
<line x1="200" y1="180" x2="200" y2="271" stroke="#64748B" stroke-width="2"/>
<polygon points="194,269 200,280 206,269" fill="#64748B"/>
<rect x="185" y="220" width="30" height="16" rx="3" fill="#F8FAFC"/>
<text x="200" y="232" font-size="8" text-anchor="middle" fill="#64748B">API</text>
```

## 附加元素

### 右侧信息框

位置：图表右侧，与层级对齐

```
┌────────────────────┐  ┌─────────────────┐
│    Layer 1         │  │   相关资源       │
├────────────────────┤  │   • 文档链接     │
│    Layer 2         │  │   • API 参考     │
├────────────────────┤  │   • 示例代码     │
│    Layer 3         │  └─────────────────┘
└────────────────────┘
```

内容可包括：
- 相关链接
- 补充说明
- 资源列表
- 版本信息

### 底部备注

位置：图表底部

```svg
<text x="400" y="580" font-size="10" fill="#94A3B8" text-anchor="middle">
  图 1: 系统架构示意图 | 版本 1.0 | 2024-01
</text>
```

## 层级标题

每层可有可无的标题，位于层的左侧或上方：

```svg
<!-- 左侧标题 -->
<text x="20" y="120" font-size="14" font-weight="600" fill="#2563EB">
  应用层
</text>
<text x="20" y="138" font-size="10" fill="#64748B">
  Application Layer
</text>
```

## viewBox 计算

```
viewBox = "0 0 [total-width] [total-height]"

total-width = max(所有层宽度) + 右侧信息框宽度(如有) + 左右 padding(60px)
total-height = 所有层高度之和 + 层间距之和 + 上下 padding(60px) + 底部备注高度(如有)
```

## 变体

### 紧凑型

- 层间距：60px
- 模块间距：30px
- 适用于模块较多的场景

### 宽松型

- 层间距：120px
- 模块间距：60px
- 适用于重点展示的场景

### 带图标型

- 每个模块前有图标
- 图标尺寸：24x24px
- 适用于功能说明图

## 最佳实践

1. **从上到下**：最重要的层在上，基础设施在下
2. **逻辑清晰**：层间关系一目了然
3. **视觉平衡**：同层模块大小协调
4. **信息适量**：避免单层模块过多（建议 ≤ 6）
5. **双语规范**：中文为主，英文辅助
