# Flow Detail · 流程完整性追问（方案 A 分批）

用户描述流程时，通常只给"主线骨架"（"下单→支付→发货"）。但一张**完整的流程图**需要：判断点的分支、异常回退、边界条件、并行汇合、清晰起止。如果直接按主线画，出来的图会缺真正的业务复杂度。

本文定义一套**分批追问方法**：抽取主线后、生成前，系统性地追问用户补全流程细节。每轮只问 2-3 个最关键的缺口，避免吓跑用户。

## 核心理念

1. **追问是为了补缺口，不是凑字数** —— 只问"缺了会让流程断裂或失真"的细节
2. **分批，每轮 ≤3 个** —— 用户答完一批，补全结构，再问下一批
3. **每个问题都带"跳过/不确定"** —— 用户不想深究就放过，用主线画
4. **最多 2 轮** —— 再多就先画出来让用户看着改，比空想强

## 第 0 步：判定要不要追问

不是所有流程图都要深挖。先看触发条件：

| 场景 | 是否追问 |
|------|---------|
| 流程含「审核/审批/检查/校验/验证」类步骤 | ✅ **必问**（这类必有通过/不通过分支） |
| 流程 > 5 步 | ✅ 问异常路径 |
| 用户明确说「详细/完整/仔细」 | ✅ 全面追问（5 类都问） |
| 流程含「退款/支付/订单」等有金额语义的词 | ✅ 问边界条件（阈值） |
| 流程只有 2-3 步且无判断 | ❌ 不问，直接画 |
| 用户明确说「简单画一下/大概就行」 | ❌ 尊重，不追问 |

**多个条件命中 → 取并集追问**。例如"退款流程（>5步 + 含审核 + 金额语义）"三类都触发，全面追问。

## 第 1 步：识别流程缺口

抽取主线后，对照下面 **5 类细节**，找出主线里缺失的部分。每类给"识别信号"和"追问模板"。

### 类 1：判断点与分支（最重要）

**识别**：主线里有这些词，但没有对应的分支：
- 审核 / 审批 / 检查 / 校验 / 验证 / 评估 / 判断
- 是否 / 能否 / 通过 / 符合

**缺口**：这些步骤后面应该有菱形决策 + 多条分支，但用户没说结果有几种、各走哪。

**追问模板**（AskUserQuestion）：
```
question: "「[审核步骤名]」这一步的结果有几种？分别走哪？"
header: "分支"
options:
  - label: "通过/不通过"  description: "二选一：通过→继续；不通过→[追问走哪]"
  - label: "多档（如低/中/高风险）"  description: "多选一，每档不同处理"
  - label: "无判断"  description: "这步只是执行，不分流"
  - label: "跳过"  description: "按主线画，不细分"
```

如果选"通过/不通过"，**紧接着追问"不通过走哪"**（文字或再一个 AskUserQuestion）：
- 驳回回退（回到前面某步）→ 标记为回环
- 直接终止（流程结束）→ 标记为失败结束
- 转人工/转其他流程 → 标记分支

### 类 2：异常与回退路径

**识别**：主线是"快乐路径"（happy path），全是通过的。真实流程必有异常。

**缺口**：没有驳回重试、超时取消、错误处理。

**追问模板**：
```
question: "流程里有没有需要回到前面重做的情况？"
header: "回退"
options:
  - label: "有驳回重试"  description: "如审核不过→补材料→重新提交（回到前面）"
  - label: "有超时取消"  description: "如买家不退货超时→自动关闭"
  - label: "都没有"  description: "纯正向流程"
  - label: "跳过"  description: "不确定，先不画"
```

### 类 3：边界条件（阈值）

**识别**：流程涉及金额、数量、等级、地域等可能触发不同路径的变量。

**缺口**：没说阈值，画的时候不知道该不该分流。

**追问模板**：
```
question: "有没有金额/数量阈值导致走不同路径？"
header: "阈值"
options:
  - label: "有金额阈值"  description: "如小额仅退款、大额人工审（文字补充阈值）"
  - label: "有等级/地域差异"  description: "如 VIP 快速通道、海外走跨境"
  - label: "无阈值"  description: "所有情况走同一路径"
  - label: "跳过"
```

选"有金额阈值" → 文字追问"阈值大概多少？超过和没超过分别走哪？"

### 类 4：并行与汇合

**识别**：步骤描述里出现"同时""并""一起""分别"。

**缺口**：没说是先后还是同时，也没说在哪里汇合。

**追问模板**：
```
question: "有没有同时进行的步骤？在哪里汇合？"
header: "并行"
options:
  - label: "有并行分支"  description: "如退款同时通知买家+触发对账（文字说哪几步）"
  - label: "都是串行"  description: "一步做完才下一步"
  - label: "跳过"
```

### 类 5：起止边界

**识别**：流程的起点和终点不明确。

**缺口**：没说由谁/什么触发，没说有几种结束状态。

**追问模板**：
```
question: "这个流程怎么开始、怎么结束？"
header: "起止"
options:
  - label: "用户发起，单一成功结束"  description: "如买家主动退款，退款完成结束"
  - label: "用户发起，多个结束"  description: "如成功结束 / 失败终止 / 超时关闭"
  - label: "系统/定时触发"  description: "如定时任务扫描自动退款"
  - label: "跳过"
```

## 第 2 步：分批执行

不要一次性甩 5 类问题。按这个流程：

### 轮次规划

把识别出的缺口按**对主结构的影响**排序，每轮挑 2-3 个最关键的：

| 优先级 | 哪些缺口 |
|--------|---------|
| 第 1 轮（必问） | 类 1（判断分支）+ 类 2（回退）—— 缺了流程会断 |
| 第 2 轮（推荐） | 类 3（阈值）+ 类 5（起止）—— 缺了流程不完整但不至于断 |
| 第 3 轮（可选） | 类 4（并行）—— 通常流程里并行少 |

### 单轮执行

1. 用**一个 AskUserQuestion 同时问 2-3 个问题**（工具支持多 question）
2. 文字简短交代背景："我先把主线画出来了，但有 N 处影响完整性的细节想确认："
3. 每个问题带"跳过"选项
4. 收到回答 → 补全 structured-content（加菱形/分支/回环）→ 如果还有缺口，进入下一轮

### 停止条件

满足任一就停止追问，进入生成：
- 所有 5 类都问过了（或用户都选了"跳过"）
- 已追问 2 轮（第 3 轮只在用户明确要"详细"时才进行）
- 用户说"够了/就这些/先画吧"

## 第 3 步：补全 structured-content

追问得到的细节，回填到 structured-content.md：

- 判断点 → 加菱形节点（D1/D2...）+ 出线条件
- 回退 → 加回环节点（虚线）
- 阈值 → 在对应菱形条件里写明（如"金额<50？"）
- 并行 → 加 AND 网关 + 汇聚
- 起止 → 加开始/结束椭圆节点

**回填后简短复述给用户**："根据你的回答，流程补全为：[复述关键分支]。这样画对吗？"给最后一个确认机会。

## 追问措辞规范

1. **不要问技术词** —— 问"审核不过走哪"，不问"排他网关的否分支指向"
2. **每个选项说人话** —— "驳回重试"而非"回环至前置节点"
3. **承认不确定** —— "我不确定这里有没有阈值"而非"请提供阈值"
4. **先给主线再追问** —— 让用户看到"已经有东西了，只是想补全"，而非"我什么都不知道"

## 与其他文档的关系

- **interaction.md**：入口提问（画什么），在 flow-detail 之前
- **structuring.md**：抽取主线结构，flow-detail 在它之后深化
- **swimlane.md**：流程图元素形状（菱形/回环等），flow-detail 决定"要不要用这些元素"

执行顺序：interaction（入口）→ structuring（抽主线）→ **flow-detail（追问补全，仅流程图）** → 确认 → 生成。

## 何时完全跳过 flow-detail

- 布局不是 swimlane（layered-stack/flow-pipeline/hub-spoke 不需要流程细节追问）
- 用户在入口提问时已经把分支、异常都说全了（主线已完整）
- 用户明确说"简单画"

判断主线是否已完整：如果用户描述里已经包含"如果...就...否则..."、"通过/不通过"、"失败的话"这类分支信号，且覆盖了所有审核步骤，就视为完整，跳过追问。
